# ลอยกระทง HCU

เกมลอยกระทงออนไลน์ของมหาวิทยาลัยหัวเฉียวเฉลิมพระเกียรติ (HCU) สำหรับอีเวนต์ 1 วัน เปิดเล่นผ่านเบราว์เซอร์มือถือได้ทันที ไม่ต้องติดตั้งแอป

ผู้เล่นเลือกตัวละครนักศึกษา HCU ตั้งชื่อ เลือกกระทงกับคำอธิษฐาน แล้วเดินบนสะพานท่าน้ำหน้าซุ้มประตูมหาวิทยาลัยไปวางกระทงลงแม่น้ำร่วมกับเพื่อนแบบเรียลไทม์

## ฟีเจอร์

- ตัวละครฐานเดียวแบบ unisex แต่งตัวได้อิสระ 4 หมวด: ทรงผม (5 แบบ + 6 สี), เสื้อ, ท่อนล่าง และรองเท้า (หมวดละ 4 แบบ) มีปุ่มสุ่มลุค
- ตัวละครหัน 4 ทิศตามทางที่เดิน มีท่ายืน เดิน ย่อตัววางกระทงแล้วไหว้ โบกมือ สาธุ ส่งหัวใจ และเงยหน้ามองพลุ
- กระทง 8 แบบ: เทียนหมี, กระทงอากาศ, กระทงน้ำแข็ง, ใบตองคลาสสิก, ธีม HCU, ดอกบัว, ขนมปังรูปเต่า และรูปปลา เลือกผ่านแถบเลื่อนที่มีลูกศร จุดบอกตำแหน่ง ป้าย “เลื่อนดูแบบอื่นอีก” และปุ่มดูทั้งหมด
- เดินได้ 3 แบบ: แตะจุดบนสะพาน, กดค้างแล้วลากนิ้วตรงไหนก็ได้ (จอยสติ๊กโผล่ตรงที่นิ้วแตะ) หรือกดค้างปุ่ม WASD / ลูกศร (กด Space หรือ E เพื่อวางกระทง)
- กัปปะโผล่มาขโมยเหรียญนำโชคบนกระทง แตะให้ทันเพื่อไล่และได้เหรียญคืน +1 เหรียญนำโชค (เกิดเฉพาะในเครื่องของแต่ละคน)
- ปุ่มจุดพลุ 5 ลาย: ทองอร่าม, หัวใจ, ดอกบัว, ดาวตกสายรุ้ง, โคมนำโชค (คูลดาวน์ 6 วินาที) คนบนสะพานเห็นพลุของกันและกัน
- ฉากซุ้มประตูป้ายสามภาษา ตึกอิฐแดงสองข้างพร้อมป้ายหัวเฉียว / HCU และโคมไฟเทศกาล
- เห็นเพื่อนบนสะพานแบบเรียลไทม์ (สูงสุด 20 คน) แตะกระทงในน้ำเพื่ออ่านคำอธิษฐานและส่งกำลังใจ บอร์ด Top 10 ประจำวัน ตัวนับกระทง และการ์ดสตอรี่ 9:16
- กรองคำหยาบ จำกัดความยาว (ชื่อ ≤ 20, คำอธิษฐาน ≤ 50 ตัวอักษร) และลอยได้ 1 กระทงต่อ 30 วินาที
- เพลงบรรเลง เสียงน้ำ และเสียงพลุ สังเคราะห์ด้วย Web Audio (เริ่มแบบปิดเสียง)

## โครงสร้างไฟล์

| ไฟล์ | คืออะไร |
|---|---|
| `index.html` | ตัวเกมเวอร์ชันเดินบนสะพาน ทั้งเกมอยู่ในไฟล์เดียว |
| `classic/index.html` | เวอร์ชันแรก: วิวแม่น้ำอย่างเดียว ไม่มีตัวละคร |
| `supabase.sql` | สร้างตาราง กฎความปลอดภัย และฟังก์ชันส่งกำลังใจบน Supabase |
| `firestore.rules` | Security rules สำหรับ Firestore |
| `firebase.json` | ค่าตั้งของ Firebase Hosting |

## โหมดการทำงาน

เกมจะเลือกโหมดให้เองตามสภาพแวดล้อมที่เปิด

1. **Supabase (แนะนำ)**: ถ้าตั้งค่า `window.SUPABASE_CONFIG` ไว้ กระทงจะเก็บในตาราง Postgres และตำแหน่งตัวละครจะซิงก์ผ่าน Realtime Presence (ส่งตำแหน่งไม่เกินประมาณ 1 ครั้งต่อวินาที) แพ็กเกจฟรีรับคนพร้อมกันได้ 200 คน
2. **Firebase**: ถ้าตั้งค่า `window.FIREBASE_CONFIG` ไว้ จะใช้ Firestore แทน (การซิงก์ตำแหน่งกินโควตาอ่านฟรีเร็ว)
3. **Claude artifact**: ถ้าเปิดเป็น artifact บน claude.ai จะใช้ฐานข้อมูลและระบบเรียลไทม์ของ Claude ใช้ได้เฉพาะคนที่ล็อกอินและได้รับสิทธิ์
4. **โหมดตัวอย่าง**: ถ้าไม่มีทั้งสองอย่าง เช่นเปิดไฟล์ตรงๆ หรือเปิดบน GitHub Pages จะมีกระทงตัวอย่างและเพื่อนจำลองบนสะพาน ข้อมูลไม่ถูกบันทึก

## ตั้งค่า Supabase (แนะนำ)

1. สร้างโปรเจกต์ที่ [supabase.com](https://supabase.com)
2. เปิด SQL Editor วางเนื้อหาไฟล์ `supabase.sql` แล้วกด Run
3. คัดลอก Project URL และ anon public key จาก Project Settings → API มาใส่ใน `index.html`
   ```js
   window.SUPABASE_CONFIG = { url: "https://xxxx.supabase.co", anonKey: "eyJ..." };
   ```
4. Push ขึ้น GitHub แล้วเปิด GitHub Pages (Settings → Pages → Branch `main` / root)

## Deploy บน Firebase

1. สร้างโปรเจกต์ใน [Firebase Console](https://console.firebase.google.com) เปิดใช้ Firestore และเพิ่ม Web app
2. ใส่ค่า config ลงในบล็อก `<script>` ที่หัวไฟล์ `index.html`
   ```js
   window.FIREBASE_CONFIG = { apiKey: "...", authDomain: "...", projectId: "...", appId: "..." };
   ```
3. Deploy
   ```bash
   npm install -g firebase-tools
   firebase login
   firebase use --add
   firebase deploy
   ```

ข้อมูลแยกเก็บเป็นรายวันใน collection `krathongs-YYYY-MM-DD` และ `players-YYYY-MM-DD` ตามเวลากรุงเทพ ส่วนตัวนับกระทงอยู่ที่ `stats/YYYY-MM-DD`

> ยังไม่ได้ทดสอบโหมด Firebase กับโปรเจกต์จริง ควรลองให้ครบก่อนวันงาน ตัวกรองคำหยาบทำงานฝั่งเบราว์เซอร์อย่างเดียว ส่วน `firestore.rules` ช่วยคุมเรื่องความยาวข้อความและการกดกำลังใจได้แค่ระดับหนึ่ง
